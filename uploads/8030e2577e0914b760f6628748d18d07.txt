Content Guardian Extension | Beginner Roadmap | Page 2
What Are We Building?
We are building a BROWSER EXTENSION — a small add-on that lives inside your Chrome or Firefox
browser. It watches what you are streaming on Netflix, Amazon Prime, Disney+, etc. When an 18+ scene is
about to play, it warns you in advance and puts a black screen over the video until the scene is over.
Simple Explanation of How It Works
1 Watch the video time
The extension checks the video every half second to know exactly where you are in the movie or
show. Think of it like a timer that keeps track of the current minute:second.
2 Check a list of scenes
We have a database (basically a big list) that stores the exact time when bad scenes start and end.
Example: "In Breaking Bad Season 2 Episode 3, the bad scene starts at 14 minutes 22 seconds
and ends at 14 minutes 58 seconds."
3 Give a warning 10 seconds early
When the video is 10 seconds away from a listed scene, a pop-up message appears saying
"Warning: 18+ scene coming up!" This gives you time to look away or prepare.
4 Cover the screen
At the exact moment the scene starts, a black screen appears over the video. You cannot see the
scene, but the video keeps playing in the background.
5 Remove the cover automatically
When the scene ends, the black screen disappears by itself and you can continue watching
normally. No action needed from you!
TIP Is this actually possible? YES! Many extensions like this exist already (example: Netflix Party, Enhancer for
YouTube). A browser extension is one of the easiest real-world projects you can build as a beginner.

In this phase you build the basic structure of the extension — like building the frame of a house before adding

3 Load the extension in Chrome and see it work
3 Write a content script that runs on Netflix

→ How Chrome reads the manifest.json file

YOUR TASKS FOR THIS PHASE
1 Create a folder called "content-guardian" on your computer
2 Inside it, create manifest.json with the basic fields: name, version, manifest_version (set to 3), permissions,

Phase 2 Detect the Video and Track Time Weeks 3–4
Now that the extension exists, you teach it to "watch" the video. Every half second, your code will check what
time the video is at. This is how the extension knows when a scene is approaching. At the end of Phase 2,
you will see the current video timestamp printed in the browser console in real time.
WHAT YOU WILL DO
3 Find the video element on Netflix and Prime pages
3 Read the video.currentTime property every 500ms
3 Detect when the user pauses, seeks, or skips
3 Identify which show/movie is currently playing
3 Match the current URL to a show ID
WHAT YOU WILL LEARN
→ How JavaScript setInterval works (run code
repeatedly)
→ How to read properties from HTML elements
→ What event listeners are and how to use them
→ How to get information from a URL using
JavaScript
→ Why DRM protects video files (and why that is
okay)
YOUR TASKS FOR THIS PHASE
1 In content.js, write: const video = document.querySelector("video")
2 Use setInterval to run a function every 500 milliseconds
3 Inside that function, log video.currentTime to the console
4 Open Netflix, play any video, open DevTools — you should see numbers increasing every 0.5 seconds in
the console
5 Add an event listener for the "seeked" event so you know when someone jumps to a different part of the
video
6 Extract the show title from the Netflix page title (document.title) and log it
TIP The video.currentTime property gives you the time in SECONDS. So 90.5 means 1 minute and 30.5
seconds into the video. You will use this number to compare against your scene database.

Phase 4 Connect the Scene Database Weeks 7–8
This is where the extension becomes smart. You will create a database of scene timestamps and connect

3 Create a Supabase database with a "scenes" table
3 Add test data: a few real timestamps from a
popular show
3 Fetch scene data from Supabase when a show
starts
3 Compare video.currentTime to the fetched
timestamps
3 Trigger the overlay automatically when a match is
found
3 Trigger the warning 10 seconds before the scene
WHAT YOU WILL LEARN
→ What a database table is (like a spreadsheet)
→ How to use fetch() to get data from the internet
→ What JSON is (the format data travels in)
→ How to compare two numbers in JavaScript
→ How async/await works (waiting for data to arrive)
YOUR TASKS FOR THIS PHASE
1 Go to supabase.com, create a free project, create a table called "scenes" with columns: id, show_id,

2 Manually add 2-3 rows for a show you know well (look up timestamps on sites like doesthedogdie.com)
3 In content.js, use fetch() to call the Supabase API and get scenes for the current show
4 Store the result in a variable called currentScenes
5 In your setInterval function, loop through currentScenes and check if video.currentTime is within any

6 If yes: call showOverlay(). When video.currentTime > end_sec: call hideOverlay()
7 Test with the show you added data for — the blackout should happen automatically!
TIP Start with just ONE show and ONE scene. Get that working perfectly before adding more. Once one scene
works automatically, adding more is just a matter of adding more rows to the database.

Phase 5 Add the AI Detector (Smart Fallback) Weeks 9–12
Your database only covers shows you have manually added. But what about shows that are NOT in the
database? This is where AI comes in. The extension will take a screenshot of the video every 3 seconds and
use an AI model (NsfwJS) to check if the frame contains adult content — completely on your device, nothing
is uploaded to the internet.
WHAT YOU WILL DO
3 Load the NsfwJS library into the extension
3 Use Canvas API to take a "screenshot" of the
video every 3 seconds
3 Pass that screenshot to NsfwJS to get a content
score
3 If the score is above 85%, trigger the overlay
3 Combine database detection (Phase 4) with AI
detection (Phase 5)
3 Add a sensitivity slider in the settings popup
WHAT YOU WILL LEARN
→ What the Canvas API is and how to draw a video
frame on it
→ What a machine learning model is (in simple
terms)
→ How to load an external JavaScript library
→ What a confidence score/probability means
→ How to combine two different systems to make
one stronger one
YOUR TASKS FOR THIS PHASE
1 In your manifest.json, add the NsfwJS library file or load it from a CDN
2 Write a function called captureFrame() that: creates a canvas element, draws the current video frame on it,
and returns the image data
3 Write a function called checkFrame() that calls captureFrame() and then passes the result to the NsfwJS
model
4 NsfwJS returns scores like: { sexy: 0.12, porn: 0.87, hentai: 0.01 }. If porn + sexy > 0.85, call showOverlay()
5 Use setInterval to call checkFrame() every 3 seconds
6 Add a slider in popup.html labelled "AI Sensitivity" that saves the threshold value to chrome.storage
TIP NsfwJS is not perfect. It will sometimes flag a romantic scene that is not explicit (false positive) or miss a
scene (false negative). The database from Phase 4 handles known scenes accurately. AI handles
unknown content as a best-effort fallback.

Problems You Will Face (And How to Solve
Them)
Every beginner faces these challenges. Knowing about them in advance means you will not be surprised
when they happen!
01 Netflix blocks direct access to video data
Netflix protects its videos with something called DRM (Digital Rights Management). This means you
cannot read the actual video file. BUT — you can take a screenshot of what is visible on screen using
something called the Canvas API. This is perfectly allowed!
Solution: Solution: Use Canvas API to capture what is shown, not the raw file.
02 The video time is not always perfectly accurate
When a viewer pauses, rewinds, or the internet is slow, the video clock can jump around. If you only
check the exact second, you might miss the scene trigger.
Solution: Solution: Add a buffer of plus or minus 5 seconds around every scene timestamp.
03 Netflix keeps changing its website code
Netflix regularly updates how their website is built. This can break parts of your extension that depend
on specific HTML elements.
Solution: Solution: Use the video element directly (document.querySelector("video")) instead of
Netflix-specific class names. The video tag never changes.
04 The scene database will never be complete
There are thousands of shows and movies. You cannot manually add timestamps for all of them by
yourself.
Solution: Solution: Start with the top 100 most-watched titles. Use AI detection as a fallback. Let your
users report missing scenes.
05 The AI might be too slow and use too much CPU
If you run the AI scene detector every second, it will slow down the computer and drain the laptop
battery.
Solution: Solution: Run the AI check only once every 3 seconds. Use TensorFlow.js which is
optimised for browsers and uses the GPU, not the CPU.
